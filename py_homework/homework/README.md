# Python 進度表（C 轉 Python 專用）

## 為什麼這樣排

你的 C 資料夾（51 個檔案）證明了一件事：**程式觀念你有了**。
函式原型宣告、指標傳出多個值、malloc/free/NULL、`&ptr[i] == &(*(ptr+i))` —— 這些不是抄得來的。

所以這份進度表不教「什麼是函式」「什麼是迴圈」，那些你會。
**它只教一件事：同一個觀念，Python 怎麼寫。**

## 怎麼寫

1. **檔案開頭的說明就是教學**，從頭讀完再動手，那不是廢話
2. 把 `pass` 換成你的程式碼
3. 第 1~12 天檔案最下面有**自動測試**，直接執行看到 `OK` 就過
4. 第 13~14 天沒有測試，照「自我檢查」清單自己確認

```
第1題 OK                              ← 過了
第1題 錯，half(7)給了 3.5，應該是 3    ← 沒過，會告訴你差在哪
```

---

## 三個一定要養成的習慣

1. **縮排一律 4 個空格** —— 你舊檔案有 1 格、2 格混用，Python 不像 C 有 `{}` 兜著，縮排錯了語意就錯了
2. **函式負責算（`return`），主程式負責印（`print`）** —— 你在 C 的 `bmi()` 做對了，Python 也一樣
3. **筆記改成記「我踩過的坑」，不記語法** —— 語法查得到，坑查不到

## 你目前確認過的 3 個跨語言錯誤模式

這三個你在 C 和 Python **各犯一次**，是真正該練掉的東西：

| 模式 | C 的證據 | Python 的證據 |
|---|---|---|
| 初始化放錯位置 | `guess3.c` / `paper.c`：`srand()` 在函式裡，每次呼叫都重設 | `paperscissor.py`：`random.choice` 在迴圈外，整場同一拳 |
| 複製貼上疊 if 必漏 | `paper.c` case 0（剪刀）判斷寫錯 | `paperscissor.py` 布那段印成「剪刀」 |
| 魔術數字寫死 | `array2.c`：有 `#define size` 卻寫 `total / 10.0` | `2D.py`：`range(4)` / `range(3)` 寫死 |

第 8 天和第 14 天專門根治前兩個。

## C 那邊也有兩個真 bug（想練 C 再處理）

- `pointermalloc.c`：`if (*ptr == 0)` 應該是 `if (ptr == NULL)` —— 先解參考才檢查，malloc 失敗時當場崩潰
- `function5.c` 的 `prime()`：`while(x<n)` 裡沒有 `x++`（無限迴圈）、宣告 `bool` 卻 `return n`、有路徑沒 return、用全域變數傳狀態
